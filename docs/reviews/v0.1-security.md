Role per PROJECT_SPEC.md section 0.1/43.3: threat model, credential
crypto, SSRF/SQLi, parser sandbox and malicious-input handling,
PII/ACL export privacy, connector read-only guard, CI/security checks,
cross-workspace/scale tests. This document is a working review record,
not a personal or agent contributor credit; see PROJECT_SPEC.md section
0.1's cross-review protocol and section 43.3's "no role is named as a
contributor/agent in the repository" instruction.

## Scope completed

Reviewed the full v0.1.0 tree (M0-M6: core, pipeline, governance,
connectors, reconciliation/policy, CLI, reports) against this project's
own HARD RULES and PROJECT_SPEC.md's security-relevant requirements
(sections 34, 38, 40, 42). Also wired and reviewed the one piece of

reconcile` CLI command (`src/ragledger/cli/commands/reconcile_cmd.py`),

## Decisions and ADR references

No new ADR was needed for this pass; the one substantive design
decision -- `ragledger reconcile`'s exit-code scheme -- reuses
`ragledger.reconcile.report`'s already-established `EXIT_PASS=0`/
`EXIT_POLICY_FAIL=1`/`EXIT_EXECUTION_ERROR=2` convention rather than
the CLI's generic `ragledger.cli._exit` eight-value table (documented
in `reconcile_cmd.py`'s own module docstring, since that module's
scheme was purpose-built by the M6 reconciliation work specifically so
CLI wiring could reuse it verbatim rather than re-litigate exit-code
semantics). See `docs/architecture/adr/` for the pre-existing ADRs this
release otherwise follows unchanged.

## Security checks

Every check below was actually executed during this review, not
assumed from earlier milestone notes. Commands are trimmed for length;
full output is reproducible by re-running them.

**1. Synthetic PII/canary fixture values must not leak outside
`tests/`.** Searched for every canary value used across the test suite
(`canary.leaktest@example.com`, `555-010-1199`, and the reconciliation
canary's `123-45-6787`/`jane.doe@example.com`) in `src/`, `docs/`,
`README.md`, `CHANGELOG.md`, and `IMPLEMENTATION_STATUS.md`:

```text
$ grep -rn "canary.leaktest\|555-010-1199\|123-45-6787\|jane.doe@example.com" \
    src/ docs/ README.md CHANGELOG.md IMPLEMENTATION_STATUS.md
(no output; grep exit code 1)
```

Clean. Every occurrence of these values lives under `tests/fixtures/`
or `tests/*/test_*.py`, which is the intended, deliberate use (canary
tests that assert these values do NOT leak into manifest/report
output -- `tests/governance/test_pii_leak_canary.py`,
`tests/cli/test_report.py::test_report_no_canary_pii_value_leaks_into_json_or_html`,
`tests/reconcile/test_pii_masking_canary.py`,
`tests/cli/test_reconcile.py::test_reconcile_masked_evidence_canary_json_html_and_stdout`).

**2. Emoji scan.** Every `.py`/`.md`/`.yml`/`.yaml`/`.json`/`.toml`/
`.txt` file outside `.venv`/`.git`/build caches (172 files as of the
final pass, after this document and its two sibling review documents
were added; this environment has no `.git` directory to query
"tracked" files from, so this is a full source-tree scan instead) was
checked for common emoji/pictograph Unicode ranges:

```text
$ grep -lP "[\x{1F300}-\x{1FAFF}\x{2600}-\x{27BF}\x{1F000}-\x{1F0FF}\x{2190}-\x{21FF}\x{2B00}-\x{2BFF}]" <files>
(no matches)
```

Clean.

**3. AI/agent/model attribution scan** (`grep -i
"co-authored|generated by|claude|anthropic|gpt|copilot"` over the same
172-file set, excluding `uv.lock`):

```text
$ grep -ilE "co-authored|generated by|claude|anthropic|gpt|copilot" <files>
./CHANGELOG.md
./PROJECT_SPEC.md
./docs/reviews/v0.1-security.md
```

Three hits, all inspected, none a real violation:

- `PROJECT_SPEC.md:26` is the specification's own text of the rule
  being checked for ("`Co-authored-by`, model/agent adı, bot Git
  identity'si, generated-by ibaresi ve `CONTRIBUTORS.md` yasaktır" --
  the source of the rule, not a violation of it). No change needed.
- `CHANGELOG.md`'s `## 0.1.0` `### Fixed` entry quotes the exact
  removed string ("Generated by ragledger report.") as part of
  documenting the fix below. Quoting a removed string in a changelog
  entry is not attribution.
- `docs/reviews/v0.1-security.md` (this file) matches its own quoted
  grep pattern and quoted match list, i.e. this section. Also not
  attribution.

The one real finding this scan caught, fixed before any of the above:
`src/ragledger/reports/_html.py:59` had every HTML report's footer
read `"Generated by ragledger report."`. This is tool
self-identification, not AI attribution, but it literally contains the
banned "generated by" phrase this project's own rule 7 prohibits
verbatim, and there is no reason to keep a self-identification string
this close to the letter of a hard rule. **Fixed**: changed to
`"ragledger report."` (no HTML structure change, only the footer
text). Re-verified: `uv run ruff check`, `ruff format --check`, and
`mypy` all pass on the changed file, and `tests/reports`,
`tests/cli/test_report.py`, and `tests/cli/test_reconcile.py` (the
three suites that render an HTML report) all still pass (32 passed).
No test asserted on the old footer string.

**4. TODO/TBD/placeholder/FIXME scan**, excluding `tests/` and
`PROJECT_SPEC.md` itself (which discusses these terms as part of the
rule text):

```text
$ grep -inE "\bTODO\b|\bTBD\b|\bplaceholder\b|\bFIXME\b" <files>
IMPLEMENTATION_STATUS.md: "... closed placeholder whitelist ..." (FR-033 row)
src/ragledger/connectors/pgvector.py: sql.Placeholder() (psycopg SQL placeholder API)
src/ragledger/core/manifest.py: "null, not a placeholder" (docstring explaining JSON null semantics)
src/ragledger/pipeline/chunkers/base.py: "template placeholder" (contextualization template feature)
```

All four are legitimate technical uses of the word "placeholder"
(a chunker template feature, psycopg's own `Placeholder` SQL API, and
a docstring explaining JSON-null-vs-absent-key semantics), not
unfinished-work markers. No `TODO`, `TBD`, or `FIXME` marker exists
anywhere in the scanned tree.

**5. Connectors expose no mutation methods.** Searched
`src/ragledger/connectors/*.py` for `PUT`/`DELETE`/`INSERT`/`UPDATE`/
`PATCH`/`DROP`/`ALTER`/`TRUNCATE`/`GRANT` usage:

```text
$ grep -nE "\b(PUT|DELETE|INSERT|UPDATE|PATCH|DROP|ALTER|TRUNCATE|GRANT)\b" src/ragledger/connectors/*.py
qdrant.py:75:    always rejected, so an accidental or adversarial PUT/DELETE/PATCH
pgvector.py:87:    read query -- INSERT, UPDATE, DELETE, every DDL statement, COPY,
```

Both hits are docstring prose describing what the guard *blocks*, not
code that issues those verbs. Confirmed by reading the surrounding
code: `qdrant.py::_is_allowed_request` is a closed allowlist (`GET
/collections/{name}`, `GET /aliases`, `POST .../points/scroll` only;
every other method/path returns `False` and is rejected by
`_guard_request`, an `httpx` request event hook run before the
transport ever sees the request). `pgvector.py::_assert_read_only_statement`
matches only a leading `SELECT`/`SHOW` via `_ALLOWED_STATEMENT_RE`; anything
else raises `ConnectorMutationBlockedError` before `_GuardedCursor.execute`
runs it, and the connection itself is additionally opened with
`read_only=True` at the database/transaction level. Neither connector's
public interface (`VectorTargetConnector`, `src/ragledger/connectors/base.py`)
declares a mutation method at all. Confirmed by test:
`tests/connectors/test_qdrant.py::test_guard_*` (parametrized over
PUT/DELETE/PATCH/POST-elsewhere), `tests/connectors/test_pgvector.py::
test_assert_read_only_statement_blocks_mutations` (parametrized over
INSERT/UPDATE/DELETE/DROP/ALTER/TRUNCATE/CREATE/GRANT/COPY).

**6. Manifest determinism** -- see "Automated tests and commands"
above; re-run directly, not cited from memory.

**7. Parser sandbox.** `ragledger.pipeline.parsers.sandbox.run_sandboxed`
runs every parse in a subprocess with a timeout and output-size cap;
`tests/pipeline/parsers/test_parser_sandbox.py` covers a hang, a crash,
an unhandled exception, a hard `os._exit`, and oversized output, all
degrading to a `status="fail"` record rather than propagating into the
host process. Re-read, not modified; no defect found.

**8. Secrets in CLI output.** `ragledger.cli._exit.CliError`'s own
docstring states the invariant ("never construct this with a secret
value interpolated into `message`"); spot-checked every `CliError(...)`
call site added or touched this session (`reconcile_cmd.py`) -- none
interpolates a credential, private key, or DSN. `key generate` writes
the private key file at mode `0600` and never echoes its bytes.

## Known limitations within declared non-goals

Per PROJECT_SPEC.md section 5.2's non-goals, the following are
intentionally absent and are not security gaps for v0.1.0:

- No RAG chat/search frontend, no retrieval-quality or LLM-response
  evaluation surface exists to secure, because none exists at all.
- No automated remediation execution against a live target: the
  remediation planner (`ragledger.reconcile.remediation`) only ever
  proposes candidates; there is no code path anywhere in this release
  that could execute one, so "automatic remediation" has no attack
  surface to review.
- No live CDC/streaming ingestion, no SaaS source connectors (Drive/
  SharePoint/Confluence), no SAML/SCIM, no arbitrary-plugin web
  execution mode -- none of these subsystems exist in this release.
- Live integration tests (`tests/connectors/test_integration.py`)
  against real Qdrant/pgvector services were not executed in this
  review (no docker commands permitted in this environment); the
  read-only guards they exercise were instead verified by direct code
  reading (item 5 above) and by the unit-level guard tests, which do
  run.
- This review's "tracked files" scans are full-source-tree scans, not
  `git ls-files`-scoped ones: this working copy has no `.git`
  directory in this environment, so there is no git index to query.
  The scan set (172 files, every `.py`/`.md`/`.yml`/`.yaml`/`.json`/
  `.toml`/`.txt` outside `.venv`/build caches) is a reasonable
  superset of what `git ls-files` would return, not a subset, so this
  does not weaken the scan's conclusions.
