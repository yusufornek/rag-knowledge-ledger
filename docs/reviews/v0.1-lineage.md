## Security checks

Owned primarily by the security/governance review; from this role's
domain-model angle, the checks specific to lineage correctness:

- **Fingerprint stability** (`Finding.fingerprint`, section 14.5): no
  timestamp or free-text message is an input to
  `ragledger.reconcile.taxonomy.compute_fingerprint`; confirmed by
  reading `build_finding`'s signature (no timestamp parameter exists
  at all) rather than only trusting the docstring's claim.
- **PII/ACL masking is structural, not a policy toggle**:
  `ragledger.reconcile.engine._compare_matched_pair` always calls
  `mask_acl_entries` before evidence reaches a `Finding`, unconditionally
  -- there is no code path that constructs ACL evidence any other way.
  Confirmed by reading every call site of `mask_acl_entry`/
  `mask_acl_entries` in `src/ragledger/reconcile/` (two call sites,
  both in `engine.py`, both unconditional).
- **Severity downgrade guard**: `build_finding` raises
  `SeverityOverrideError` if a caller passes a non-critical severity for
  a critical-by-default code without an explicit
  `severity_override_reason`; confirmed no call site in `engine.py`
  ever supplies a real reason string (`grep -n
  "severity_override_reason=" src/ragledger/reconcile/engine.py`
  matches only the one line where the local `_finding` helper forwards
  its own `severity_override_reason` parameter to `build_finding` --
  and every one of `_finding`'s own call sites in `engine.py` either
  omits that parameter entirely or passes `severity=None`, so it is
  always `None` in practice today. This release never exercises the
  override path -- worth recording since the escape hatch exists in the
  type signature but nothing in this codebase currently supplies a
  reason through it).

## Known limitations within declared non-goals

Per PROJECT_SPEC.md section 5.2:

- **Raw embedding vectors are never in the manifest** (explicit
  non-goal: "Raw embedding vectorları manifest JSON içine gömme").
  `ragledger.core.models.EmbeddingRecord` has no vector field; this is
  a structural guarantee (the type does not exist to populate), not a
  runtime check that could be bypassed.
- **License legal-compliance decisions are out of scope** ("License
  hukuki uygunluk kararı; yalnız assertion ve unknown/risk").
  `ragledger.governance.license` and `ragledger.reconcile.policy`'s
  license handling only ever produce an SPDX expression assertion or a
  policy allow/deny/unknown verdict -- never a legal-compliance
  judgment. Confirmed no string in either module claims legal
  correctness.
- **Retrieval quality and LLM response accuracy are out of scope**
  ("Retrieval quality evaluation", "LLM response/citation doğruluğu").
  Nothing in `ragledger.pipeline.embedding` or `ragledger.reconcile`
  measures or claims anything about retrieval relevance; the
  deterministic reference embedder is explicitly documented (in its
  own docstring and in `README.md`'s Limitations section) as carrying
  no learned semantic meaning.
- **FR-125/FR-126 (idempotent cached result, reconciliation history
  diff) remain `pending`.** `Finding.fingerprint`'s stability is the
  primitive a cache/diff layer needs, but no such layer exists; this
  matches `m6-status-notes.md`'s own "explicitly out of scope" framing,
  now also reflected as `pending` (not `implemented`/`partial`) in
  `IMPLEMENTATION_STATUS.md`.
- **Index bindings are not produced by `ragledger build`.** The
  reconciliation engine's "expected" side
  (`ragledger.reconcile.matching.resolve_expected_points`) is fully
  implemented and tested against a populated `IndexBinding` list
  (`tests/reconcile/builders.py::make_scenario`/`make_bulk_dataset`),
  but nothing in `ragledger.pipeline.build` populates that list from a
  standalone CLI build -- documented in `ragledger.pipeline.build`'s
  own module docstring as scope belonging to connector/target
  configuration, and repeated honestly in `README.md`'s quickstart and
  Limitations section rather than glossed over with a misleadingly
  "complete-looking" demo.
