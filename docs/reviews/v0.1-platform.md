## Decisions and ADR references

`ragledger reconcile`'s CLI signature
(`ragledger reconcile MANIFEST SNAPSHOT [--policy FILE] [--output
report.json] [--html report.html] [--work-dir DIR]
[--big-data|--auto]`) was built to match PROJECT_SPEC.md section
17.1's literal example (`ragledger reconcile manifest.json
snapshot.ndjson.zst --policy policy.yml`) plus the additional flags
this session's task required. Two product-facing decisions worth
recording:

1. **No `--target`/`--scope` flags.** A `.ndjson.zst` snapshot already
   states which (target, scope) pass it is (`SnapshotHeader.target_id`/
   `.scope`, written by `ragledger snapshot` at capture time); the
   `reconcile` command reads that header via
   `NdjsonConnector.inspect_target_schema()` rather than asking the
   operator to repeat information the snapshot file already carries.
   This mirrors how `ragledger report snapshot SNAPSHOT` needs no
   separate target argument either.
2. **`--big-data/--auto`, not a numeric threshold flag.** `--auto`
   (the default) tries the in-memory path first and falls back to the
   external-merge path only if the observed snapshot turns out to
   exceed `ragledger.reconcile.engine.reconcile_small_data`'s own
   `max_in_memory_points` guard (100,000, matching that function's
   documented default). `--big-data` skips straight to the
   external-merge path. This keeps the CLI's mental model to two
   choices ("let it decide" or "force the bounded-memory path") rather
   than asking an operator to guess a byte or row-count threshold up
   front.

No new ADR file was added; both decisions are documented in
`reconcile_cmd.py`'s module docstring as the single source of truth,
consistent with this repository's existing pattern (see, for example,
`manifest_cmd.py`'s verify-exit-code docstring) of documenting a
command-level interpretation decision next to the code it governs
rather than only in a review doc.

## Security checks

Owned primarily by the security/governance review
(`docs/reviews/v0.1-security.md`); from this role's angle, the checks
specific to CLI/reporting surface area:

- No command ever echoes a secret to stdout: `key generate` writes the
  private key to a `0600` file and only ever logs its public
  fingerprint; `manifest sign --key-file` reads a key file path, never
  a key value, from the command line.
- Every HTML report (manifest, snapshot, reconciliation) is
  self-contained: verified by grepping each rendered report for
  `<script`, `http://`, and `https://` substrings (none present) as
  part of `tests/cli/test_report.py`, `tests/reports/`, and the new
  `tests/cli/test_reconcile.py::test_reconcile_html_output_is_self_contained`.
- `ragledger reconcile`'s JSON/HTML/stdout output was specifically
  re-checked for the masked-evidence guarantee from the CLI's own exit
  boundary outward (not just at the `ragledger.reconcile` library
  layer, which M6 already covered): a raw SSN and a raw ACL principal
  identifier are asserted absent from all three surfaces in
  `test_reconcile_masked_evidence_canary_json_html_and_stdout`.

## Known limitations within declared non-goals

- **No API server, persistence, or web UI in this release**, per
  PROJECT_SPEC.md section 5.2/`IMPLEMENTATION_STATUS.md`'s release
  scope. There is nothing for this role to review at that layer for
  v0.1.0; `docker-compose.yml`'s Qdrant/Postgres services exist only
  to support the connector test suite and manual/live testing of
  those connectors, not an application server.
- **`ragledger reconcile` has no `--format csv` option.**
  `RemediationPlan.to_csv_rows()` exists as a tested library method
  (`ragledger.reconcile.report`) but this pass did not wire a CLI flag
  for it, since the task's literal CLI signature
  (`[--output report.json] [--html report.html]`) did not call for
  one; recorded as a gap in `IMPLEMENTATION_STATUS.md` FR-135/FR-140
  rather than silently added or silently left undocumented.
- **`ragledger reconcile`'s `--auto` small-data guard fully
  materializes the observed stream before checking its size** (see
  `ragledger.reconcile.engine.reconcile_small_data`'s own docstring:
  "a guard rail, not a streaming bound"). This is pre-existing M6
  behavior, not introduced by this pass's CLI wiring; the CLI's
  fallback-and-retry design does not change that underlying property,
  and is documented as such in `reconcile_cmd.py`.
- **No dry-run/build-plan-preview command** (FR-080) and no `inspect`/
  `diff`/`doctor`/`serve` commands exist; unchanged from the M4 status
  notes, still out of scope for v0.1.0.
